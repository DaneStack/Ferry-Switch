# Ferry (Switch)

*[English version](README.md)*

Нативное homebrew-приложение для Nintendo Switch, превращающее консоль в FTP-сервер: файлы можно переносить на неё и с неё по Wi-Fi любым FTP-клиентом в той же сети. Полноценная замена встроенному в DBI ftpd: та же задача плюс живой экран состояния (кто подключён, что именно передаётся и с какой скоростью), выбор того, *какую* файловую систему отдавать наружу, и локальный файловый менеджер для SD-карты.

Оформление совпадает с [клиентом Ferry для macOS](https://github.com/DanilKhmyrov/Ferry) (двухпанельный клиент с поддержкой **FTP и SFTP**) — та же тёмная палитра, тот же бирюзовый акцент, та же иконка с паромом, — но внутри это обычный FTP-сервер, так что подойдёт любой клиент.

Собрано на [devkitPro](https://devkitpro.org/) (devkitA64 + libnx) и SDL2.

## Что Ferry может отдавать

На экране Server есть переключатель 2x2 — какую файловую систему FTP-сервер отдаёт в качестве корня. Активна всегда одна, и сменить её можно только пока никто не подключён.

| Корень | Что видит клиент | Доступ |
| --- | --- | --- |
| **SD Card** | `sdmc:/` — SD-карта как есть | Чтение / запись |
| **NAND** | Внутренний раздел `User` консоли | Только чтение |
| **Installed Games** | По папке на каждую установленную игру плюс папка `Installs` для загрузки | Только чтение, кроме `Installs` |
| **Saves** | По папке на каждую игру; вход в папку монтирует её сохранения | Чтение / запись внутри сохранения |

### SD Card

Вариант по умолчанию и самый обычный: SD-карта целиком, чтение и запись, ровно так же, как её показал бы любой другой FTP-сервер.

### NAND

Внутренняя память консоли — BIS-раздел `User`, — смонтированная строго только на чтение, чтобы посмотреть содержимое и сделать резервную копию. Ничего внутри этого корня нельзя записать, создать, переименовать или удалить.

### Installed Games

Синтетический список, построенный по собственной базе метаданных контента консоли. На верхнем уровне — по папке на каждую установленную игру с именем вида `Game Name [0100ABCD00000000]`, а внутри каждой — установленное содержимое этой игры в виде файлов `.nsp`: один для базовой игры и один для обновления, если оно установлено. Для игр, у которых есть и то и другое, на верхнем уровне дополнительно появляется объединённый файл `Game Name[B+U<версия>].nsp`.

Этих файлов физически нет на диске. Ferry заранее собирает заголовок контейнера PFS0 из размеров и идентификаторов контента, которые сообщает консоль, а затем по мере скачивания передаёт записи контента напрямую из `ncm` — те же данные, что показывает на этом уровне DBI, собираемые на лету.

Ещё на верхнем уровне есть папка **`Installs`**. В отличие от всего остального в этом корне, это настоящая папка на SD-карте, доступная для записи (`/switch/Ferry/Installs`): загрузите в неё `.nsp`, `.nsz`, `.xci` или `.xcz` — либо положите такой файл в корень этой файловой системы, он окажется там же, — и он будет записан на SD-карту как обычный файл, не более того.

**Ferry ничего не устанавливает.** Он не разбирает, не проверяет, не расшифровывает и не распаковывает загруженное и никогда не пишет в системное хранилище консоли. Загрузка сюда лишь кладёт файл на SD-карту; установка — отдельный шаг, который вы потом выполняете сами через DBI или другой установщик. Ferry — инструмент передачи файлов, и назначение этой папки этим и исчерпывается.

### Saves

По папке на каждую установленную игру. Вход в папку монтирует сохранения этой игры для текущего пользователя консоли и отдаёт их на чтение и запись, так что сохранение можно забрать скачиванием и вернуть загрузкой. После каждой успешной операции записи изменения фиксируются (commit) в файловой системе сохранений, а сам монтируемый том отключается, когда клиент выходит обратно наверх или отключается. Аккаунт определяется автоматически: предвыбранный пользователь, иначе последний открытый, иначе первый аккаунт на консоли.

### Модель «только чтение»

Полноценно доступен на запись только корень SD-карты. Всё остальное — только чтение, и это проверяется в одном-единственном месте: одной проверкой в диспетчере FTP-команд, через которую проходит каждая изменяющая файловую систему команда (`STOR`, `MKD`, `RMD`, `DELE`, `RNFR`, `RNTO`), а не отдельными проверками, разбросанными по обработчикам, — потому что ошибка здесь ставит под удар данные самой консоли, а не просто приводит к багу в приложении. Поведение fail-closed: всё, что явно не разрешено, получает `550 Read-only filesystem`.

Осознанных исключений ровно два, и оба узкие:

- сохранение, в которое конкретный клиент действительно вошёл, в корне **Saves** (иначе восстановить сохранение было бы невозможно), и
- папка `Installs` в корне **Installed Games** — обычная папка на SD-карте.

## Экраны и управление

Ferry запускается на экране **Server**. Пока никто не подключён, на нём показаны адрес консоли и QR-код с этим адресом (можно отсканировать вместо ручного ввода), признак того, требуется ли PIN, и четыре карточки файловых систем. Как только клиент подключается, карточки сменяются живым прогрессом по каждой передаче — имя, направление, проценты, скорость, — журналом активности и итогами текущей сессии. В шапке на обоих экранах — заряд батареи и свободное место на SD-карте.

Экран **Browse** — локальный файловый менеджер для SD-карты (всегда именно SD-карта, независимо от того, какой корень отдаёт FTP-сервер), с иконками по типам файлов.

Кнопка **-** (Minus) в любой момент открывает встроенную справку; закрывается она любой кнопкой.

### Экран Server

| Управление | Действие |
| --- | --- |
| **L / R** или тап по вкладке | Перейти на Browse |
| **Крестовина / левый стик + A** или тап по карточке | Выбрать отдаваемую файловую систему (только пока нет подключений) |
| **Y** | Без подключения: перебор SD → NAND → Installed Games → Saves. При подключении: отключить всех клиентов (с подтверждением) |

### Экран Browse

| Управление | Действие |
| --- | --- |
| **Крестовина / левый стик вверх-вниз** или тап по строке | Переместить выделение |
| **A** или двойной тап по строке | Открыть выбранную папку |
| **B** | Подняться на уровень выше |
| **Y** | Удалить выбранное (с подтверждением) |
| **X** | Создать папку (открывает экранную клавиатуру) |
| Протяжка по списку | Прокрутка |
| **L / R** или тап по вкладке | Перейти на Server |

### В любой момент

| Управление | Действие |
| --- | --- |
| **ZL** | Задать или убрать PIN, который клиенты должны присылать как пароль FTP |
| **ZR** | Переключить светлую и тёмную тему |
| **-** | Открыть или закрыть справку |
| **+** | Выйти из Ferry |

## Подключение

Сервер слушает порт **5000**. Направьте любой FTP-клиент на `<ip-консоли>:5000` — этот адрес показан на экране Server и он же закодирован в QR-коде.

По умолчанию вход анонимный. Нажмите **ZL**, чтобы задать PIN; после этого клиенты обязаны присылать его в качестве пароля FTP (в клиенте Ferry для macOS это просто поле пароля в подключении). Неверный PIN — клиент немедленно отключается. Пустой ввод PIN сбрасывает его и возвращает открытый доступ.

## Поддержка протокола

Минимальный FTP-сервер, рассчитанный на то, что реально отправляет клиент Ferry для macOS: `USER`, `PASS`, `SYST`, `TYPE`, `ALLO`, `PWD`/`XPWD`, `CWD`/`XCWD`, `CDUP`/`XCUP`, `PASV`, `LIST`/`NLST`, `RETR`, `STOR`, `MKD`/`XMKD`, `RMD`/`XRMD`, `DELE`, `RNFR`, `RNTO`, `SIZE`, `NOOP`, `QUIT`. Только пассивный режим — клиенты, которым обязателен активный (`PORT`), работать не будут.

Одновременно могут быть подключены и передавать данные до 4 клиентов — именно благодаря этому режим параллельной передачи Mac-клиента действительно работает параллельно, когда на другой стороне Switch. Все сокеты неблокирующие, и текущая команда или передача каждого клиента продвигается ограниченными шагами, так что один активный клиент не может застопорить остальных.

Сервер работает в собственном потоке с приоритетом чуть ниже интерфейсного, поэтому передача не привязана к частоте обновления экрана, а насыщенный канал не отнимает кадры. Раньше сервер жил в кадровом цикле, и это жёстко ограничивало скорость: около трёх четвертей времени передачи уходило на ожидание следующего кадра, а не на сеть или карту памяти.

`ALLO` здесь носит справочный характер: ничего не резервируется заранее, команда лишь позволяет показать в прогрессе загрузки общий размер и проценты вместо одних только переданных байт. Клиенты, которые её не отправляют, загружают файлы точно так же.

## Особенности поведения

- Пока Ferry запущен, консоль не уходит в спящий режим, поэтому простаивающее подключение не обрывается само по себе.
- Каждое подключение, отключение, передача, удаление, переименование и создание папки дописывается в `sdmc:/switch/Ferry/log.txt`, так что история переживает перезапуск приложения, хотя на экране остаются только последние записи.
- Выбор светлой или тёмной темы сохраняется в `sdmc:/switch/Ferry/config.txt` и восстанавливается при следующем запуске.
- Файлы, загруженные для последующей установки, лежат в `sdmc:/switch/Ferry/Installs`.

## Известные ограничения

- Корневую файловую систему нельзя переключить, пока подключён клиент: подмена корня под активной сессией оставила бы её текущий каталог указывающим в пустоту. Сначала отключите клиента (**Y** на экране Server) или дождитесь, пока он отключится сам.
- На команду `SIZE` для сгенерированных файлов `.nsp` в корне **Installed Games** ответа нет — их размеры берутся из листинга каталога. Клиенты, которым перед скачиванием обязателен ответ на `SIZE`, могут ругаться.
- Сгенерированные файлы `.nsp` собираются по документированной раскладке PFS0, но пока не проверялись обратной установкой на реальном железе. Считайте их непроверенными.
- Активный режим FTP не реализован.

## Сборка

Нужен настроенный `DEVKITPRO` с пакетами `switch-dev`, `switch-sdl2`, `switch-sdl2_ttf`, `switch-sdl2_gfx` и `switch-sdl2_image`:

```bash
export DEVKITPRO=/opt/devkitpro
export PATH=$DEVKITPRO/pacman/bin:$PATH
sudo dkp-pacman -S switch-dev switch-sdl2 switch-sdl2_ttf switch-sdl2_gfx switch-sdl2_image
```

Затем из этого каталога:

```bash
export DEVKITPRO=/opt/devkitpro
export DEVKITA64=/opt/devkitpro/devkitA64
export PATH=$DEVKITA64/bin:/opt/devkitpro/tools/bin:/opt/devkitpro/portlibs/switch/bin:$PATH
make
```

На выходе — `Ferry.nro` с вшитыми в него иконками типов файлов из `romfs/`.

## Установка

Скопируйте `Ferry.nro` в `/switch/Ferry/Ferry.nro` на SD-карте и запустите из Homebrew Menu (hbmenu).

Чтобы обновиться позже, загружайте новую сборку поверх существующего `Ferry.nro`, а не удаляйте файл заранее: загрузка заменяет файл на месте, а удалять пришлось бы ровно ту копию, которая сейчас запущена.

## Клиент для macOS

[Ferry для macOS](https://github.com/DanilKhmyrov/Ferry) — отдельное приложение в собственном репозитории: двухпанельный файловый клиент, локальная файловая система с одной стороны и удалённый сервер с другой, drag-and-drop в обе стороны. Он поддерживает **и FTP, и SFTP**, поэтому тем же приложением можно работать с обычными SSH/SFTP-серверами, а не только с этим.

Они делались как пара — здесь сервер, там клиент, — но друг без друга обходятся: с этим сервером работает любой FTP-клиент, а Mac-клиент работает с любым FTP- или SFTP-сервером.
